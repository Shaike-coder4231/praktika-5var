1. ЦЕЛЬ РАБОТЫ
Научиться проектировать и реализовывать сложные бизнес-операции с участием нескольких связанных сущностей. Освоить создание интерактивных форм с динамической загрузкой данных, реализацию серверных проверок с учётом конкурентного доступа, формирование пользовательских отчётов и кросс-тестирование интерфейсов в команде.

2. ИСПОЛЬЗОВАННЫЕ ТЕХНОЛОГИИ
- Backend: PHP 8+, PDO (MySQL), паттерн Repository
- Frontend: HTML5, CSS3, Bootstrap 5, Vanilla JS (Fetch API)
- Архитектура: MVC-подобная структура (Controller -> Repository -> View)
- Инфраструктура: Хостинг Beget, phpMyAdmin, Git/GitHub
- Безопасность: CSRF-токены, экранирование вывода, транзакции БД, валидация

3. ХОД ВЫПОЛНЕНИЯ РАБОТЫ
3.1. Модификация структуры БД
- В таблицу appointments добавлены поля: status (pending/confirmed/completed/cancelled), booking_code, cancel_reason, updated_at.
- Создана таблица appointment_logs для фиксации всех операций (создание, смена статуса, перенос, отмена).
- Создана таблица working_hours для хранения графика мастеров (Пн-Пт, 09:00-13:00 и 14:00-18:00).
- Учтены бизнес-правила варианта: услуги с флагом requires_consultation, связь услуг с расходными материалами (products).

3.2. Реализация уровня доступа к данным (Repository)
- Разработан AppointmentRepository с методами:
  * getAvailableSlots() - генерация свободных 15-минутных интервалов на основе графика мастера, длительности услуги и занятых записей.
  * create() - создание записи в транзакции с повторной проверкой занятости слота и генерацией уникального кода бронирования.
  * updateStatus() - изменение статуса с проверкой допустимых переходов (например, нельзя отменить завершённую запись).
  * reschedule() - перенос записи с валидацией доступности нового времени.
  * Методы агрегации для отчётов (выручка по дням, загрузка мастеров).

3.3. Контроллеры и AJAX-взаимодействие
- Создан AppointmentController, обрабатывающий маршруты создания, списка, просмотра, смены статуса, переноса и отчётов.
- Реализован эндпоинт ajax_slots.php, возвращающий JSON с доступными слотами по параметрам service_id, master_id, date.
- Внедрена защита от конкурентных бронирований: транзакция + SELECT перед INSERT + откат при конфликте.

3.4. Пользовательский интерфейс
- Форма бронирования: зависимые поля (Услуга -> Мастер -> Дата -> Кнопки-слоты). Динамическая подгрузка без перезагрузки страницы.
- Список записей: таблица с фильтрами (статус, дата, мастер), пагинацией (20 записей), цветовой индикацией статусов и AJAX-кнопками быстрой смены статуса.
- Страница переноса: предзаполненная форма с выбором нового времени из доступных слотов.
- Отчёты: таблицы статистики за выбранный месяц, экспорт в CSV (генерация на лету через php://output).
